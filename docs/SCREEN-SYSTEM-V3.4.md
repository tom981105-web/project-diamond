# V3.4 전체 화면 시각 통합

## 비교 기준

사용자가 제공한 KICKRU 플레이 화면 74장을 화면 종류별로 검토했습니다. 홈(053414), 선수(053519), 반응(053507), 기록(053817), 계약·서명(053904), 이야기(054403) 등의 정보 우선순위와 화면 밀도를 기준으로 삼았습니다. 원본 소스·캐릭터·배경·로고를 가져오지 않고 기존 PROJECT DIAMOND 자산과 독립 구현을 사용합니다. 시각적 유사도에 대한 객관적인 백분율은 산출하지 않았습니다.

## 반영 범위

| 화면 | 변경 | 기존 동작 보호 |
| --- | --- | --- |
| 홈 | 신원·종합 능력·통산 3개 수치를 먼저 표시하고, 시즌·몸 상태는 별도 요약으로 분리 | 시즌 진행과 준비 장면 버튼 유지 |
| 공통 탐색 | 상단 반응·기록 바로가기, 둥근 하단 메뉴, 진행 버튼 간격 통일 | 원래 탭 명령 사용 |
| 시즌 | 성적·기용 상황·계획·결과 카드의 위계와 글자 크기 통일 | 실제 계산·진행 중단·선택 유지 |
| 선수 | 프로필과 6개 능력치에 집중하고 준비 장면 링크를 능력치 아래로 이동 | 훈련·장기 과제·기용·계약 정보 유지 |
| 반응 | 진행 중/보관된 시즌 선택, 기사·댓글·계약 소식의 조회 범위 일치 | 저장된 기록으로 생성한 내용만 표시 |
| 기록 | 트로피 요약을 먼저 표시하고 필터·통산 성적·보관함을 정돈 | 기존 팀·연도·아마/프로 조회 유지 |
| 대화 | 장면·상황·선택지의 폭과 여백, 글자 크기 통일 | 선택 효과와 중복 방지 로직 유지 |
| 계약·서명 | 핵심 조건 4개, 펼쳐 보는 현재 계약 비교, 고정 행동, 짧은 서명 흐름 | 그리기·이름 서명 및 최종 확정 유지 |
| 결산·지난 시즌 | 제목·요약·성장·반응·하단 확인의 공통 위계 | 실제 보관 기록과 기존 탭 유지 |

`screen-system.js`는 이미 있는 화면 노드를 옮기고 조회 대상을 표시합니다. 반응 조회 연도는 화면 내 임시 선택이며 저장하지 않습니다. 별도 선택 전에는 최신 가능한 시즌을 표시하고 사용자가 고른 연도는 같은 커리어에서 유지합니다. 커리어 교체 시 초기화합니다.

## 발견한 표현 오류 수정

기존 공통 버튼 색상이 보관함의 시즌 행과 비활성 기록 탭에 적용되어 읽기 어려웠습니다. 흰 행·옅은 탭 배경과 명확한 글자색으로 수정했습니다. 반응 조회는 현재 이야기·계약 소식·지난 시즌 기사를 함께 필터링합니다.

## 데이터·검증

저장 키·형식·마이그레이션, 경기·성장·부상·계약 계산과 난수는 변경하지 않습니다. 계약 파일의 수정은 비교 영역과 이름 서명 영역의 HTML 구성뿐입니다.

320·390·832·1366px에서 탐색, 실제 시즌 진행, 기존 저장 원문 불변, 대화·계약·서명 취소, 반응 연도 필터, 보관함의 글자 대비와 상세 조회를 검사합니다. 참고 화면과 비슷한 832×940 및 모바일 화면에서 실제 커리어를 불러와 시각 검증했습니다. 전체 기존 회귀 검사를 통과한 코드만 병합합니다.
